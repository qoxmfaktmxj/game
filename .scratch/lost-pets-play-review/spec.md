# 로스트 팻츠 모바일과 데스크톱 개선안

2026-11-10 기준. 로컬 `main`과 `origin/main`은 `e14eb0db40dd`였다. 대상은 친구 두 명이 한 테이블에서 진행하는 첫 게임이다. 아래 항목은 다음 구현을 위한 제안이다.

후속 적용 범위와 플레이 검증은 [1번과 2번 작업 기록](issues/02-turn-controls.md)에 정리했다.
길 점수 미리보기와 재경기는 [3번과 4번 작업 기록](issues/03-score-and-rematch.md)에서 확인할 수 있다.

## 어디서 불편했나

연습 봇과의 첫 내 차례에 멍이 4를 골랐다. 같은 테이블, 같은 카드, 페이지 맨 위를 기준으로 잰 CSS 픽셀이다. 봇의 선후공, 닉네임 길이와 쌓인 카드 수에 따라 위치가 달라진다.

| 브라우저 크기 | 손패 영역 시작 | 놓기와 버리기 버튼 줄 시작 | 첫 화면에서 보이는 것 |
| --- | ---: | ---: | --- |
| 360 × 740 | 1,024px | 1,325px | 상대 길과 공용 더미 |
| 390 × 844 | 1,058px | 1,359px | 내 길의 윗부분까지 |
| 1024 × 768 | 1,283px | 1,528px | 한 열로 늘어난 공개판 |
| 1366 × 768 | 251px | 756px | 오른쪽에 손패 8장, 아래쪽에 버튼 윗부분 12px |

동물의 이름, 숫자, 계열색 테두리는 카드를 구별하는 데 도움이 된다. 공개 더미에서 지난 카드를 확인하고 맨 위 카드만 가져가는 동작도 잘 분리돼 있다. 개선 작업의 기준은 확정 동물 50면, 2px 계열색 테두리, 공개 카드의 원래 순서다. 버림 더미 높이 제한은 별도 디자인 결정 사항이다.

로컬 캡처는 이 폴더의 `mobile-first-turn.png`, `desktop-first-turn.png`, `mobile-result.png`에 보관했다.

## 1. 모바일에서 손패와 뽑을 곳을 바로 찾기

공개판을 읽고 있는데 내 차례가 돌아오면 화면 아래에 얇은 행동 바를 둔다. 놓기 단계에는 `내 차례 | 손패 보기`, 가져오기 단계에는 `덱에서 뽑기`와 `버림 더미 보기`를 제공한다. 손패 보기는 기존 가로 손패로, 버림 더미 보기는 공개 더미로 이동한다. 카드를 고른 뒤에는 같은 자리에서 놓기와 버리기를 선택한다. 바로가기에는 이동만 연결하고 실제 카드 이동은 명시적인 행동에서 실행한다.

항상 펼친 손패는 상대 길과 이전 카드 숫자를 가릴 수 있다. 첫 구현은 버튼 한 줄과 기존 영역으로의 이동으로 시작한다. 상대 차례에 판을 읽는 사람의 화면을 강제로 움직이지 않는다.

**완료 기준** 360 × 740과 390 × 844에서 페이지 맨 위에서도 내 차례와 할 일이 보인다. 손패와 가져올 수 있는 더미에 각각 한 번의 탭으로 도달한다. 8장을 끝까지 넘길 수 있고, 중반에도 모든 공개 카드와 맨 아래 버튼을 읽고 누를 수 있다.

## 2. 노트북에서 손패 비교와 행동을 같은 시야에 두기

1366 × 768에서는 오른쪽 네 칸씩 두 줄 손패가 유용하지만 각 카드 아래에 44px 끌기 손잡이가 반복된다. 마우스로는 이미 카드 면 전체를 끌 수 있다. 마우스 환경에서 전용 손잡이가 차지하는 공간을 줄이고 행동 바를 손패 가까이에 둔다. 터치 환경은 카드 면의 스와이프와 끌기 손잡이를 구분한다. 1024px 한 열 배치에는 모바일의 행동 바로가기를 적용한다.

카드와 손잡이가 모두 같은 카드를 선택해 키보드 초점이 두 번씩 멈춘다. 첫 손패를 선택한 뒤 버리기까지 Tab을 16번 눌렀다. 카드당 키보드 초점 하나를 두고 선택한 카드에서 행동 버튼으로 건너갈 수 있게 한다.

**완료 기준** 1366 × 768에서 스크롤 없이 손패 8장의 숫자와 놓기, 버리기 버튼 전체를 함께 본다. 1024 × 768에서도 행동을 한 단계로 찾는다. 키보드로 카드 선택 후 두 번 이내 입력으로 행동 버튼에 도달하고, 실행은 사용자가 확정한다.

## 3. 고른 카드가 어디로 가고 몇 점이 되는지 보여주기

현재 카드를 선택하면 파란 화살표가 내 길에 뜬다. 그 길을 탭하면 상세창이 열린다. 탭으로 고른 상태에는 가능한 길의 테두리를 보여주고 이동 화살표는 실제로 끄는 동안에만 표시한다. 행동 바에는 선택 결과를 적는다. 처음 연 빈 냥이 길에 5를 놓은 실제 장면이라면 `냥이 길 0점 → −15점`이다. 처음 길을 열 때만 합계에서 20점을 빼는 이유를 한 줄로 덧붙인다.

놓을 수 없는 카드에는 이유 하나를 보여준다. 예를 들어 `이미 냥이 7이 있어요. 8 이상을 놓을 수 있어요.`로 안내한다. 상대를 기다리는 동안에는 현재의 카드 선택 안내를 내린다.

**완료 기준** 길을 탭해서 살펴보거나 카드를 선택하는 동안 명령이 전송되지 않는다. 배치 가능 여부는 서버가 보낸 허용 행동을 따른다. 미리보기는 내 카드와 공개 길만 사용하고 빈 길, 음수에 적용되는 지원 배수, 8장 보너스의 실제 승인 점수와 일치한다. 숫자와 지원 카드가 각각 막히는 이유도 확인한다.

## 4. 판이 끝나면 승패와 재경기를 먼저 보여주기

두 사람이 자연 종료한 검증 판은 −43 대 −44, 한 점 차이였다. 모바일 결과 화면에서는 다음 게임 선택란을 먼저 지나고, 길별 계산표를 모두 내려야 재경기 버튼을 찾는다. 첫 화면에는 `1점 차이로 졌어요`, 두 사람의 점수와 `재경기 준비`를 모은다. 바로 아래에서 다섯 길의 계산식을 확인할 수 있게 하고 게임 변경과 봇 관리는 뒤에 둔다.

**완료 기준** 390 × 844에서 승패와 두 점수, 다음 행동이 함께 보인다. 공동 승리와 기권에는 각각 해당 종료 이유를 표시한다. 기권 승패는 점수 차로 설명하지 않는다. 두 사람이 준비한 뒤 호스트가 같은 테이블에서 새 판을 시작할 수 있다.

## 검증 범위

- 로컬 Chrome의 독립 브라우저 컨텍스트 두 개로 초대 입장, 놓기와 버리기, 44장 소진과 자연 종료, 결과, 재경기까지 진행했다. 가져오기 단계에서 새로고침한 뒤 같은 손패와 차례가 복구됐고, 상대가 나갔다 돌아온 뒤 게임을 이어갔다. `table-play.spec.ts` 5건이 통과했다.
- 카드 선택, 잘못된 드롭, 드래그 취소, 정상 드롭, 키보드 제출 및 Chromium 터치 이벤트를 사용하는 `star-animal-interaction.spec.ts` 1건이 통과했다.
- 위 수치는 로컬 Chrome에서 잰 뷰포트 결과다. 다음 구현의 출하 검증에는 실제 iPhone Safari와 Android Chrome에서의 손패 스와이프, 하단 브라우저 바, 앱 전환 후 복귀를 포함한다.

## 독립 검토 기록

디자인 검토와 브라우저 계측은 별도 플레이어와 테이블에서 진행했다. 평가자는 모바일에서 봇과 한 판을 자연 종료하고, 별도 판에서 기권과 재경기 결과도 확인했다. 기술 검토자는 390px 화면에서 손패를 337px 옆으로 넘겨 여덟 번째 카드가 모두 드러나는 것을 확인했다. 손패의 가로 스와이프는 계속 지원할 가치가 있다.

| 사용성 항목 | 4점 만점 | 관찰 |
| --- | ---: | --- |
| 현재 상태 파악 | 2 | 내 차례와 다음 행동이 휴대폰 첫 화면 아래에 있다. |
| 게임 규칙에 맞는 표현 | 3 | 카드 이름과 숫자는 명확하지만 첫 배치의 비용은 뒤늦게 알게 된다. |
| 사용자 통제 | 3 | 카드 선택, 취소, 명시적 제출이 구분된다. |
| 일관성 | 2 | 화살표가 나타난 길을 탭하면 상세창이 열린다. |
| 오류 예방 | 3 | 잘못된 배치와 방금 버린 카드 가져오기를 막는다. |
| 기억 부담 | 2 | 손패와 목적지를 오갈 때 이전 화면을 기억해야 한다. |
| 조작 효율 | 2 | 키보드 초점이 매 카드에 두 번씩 멈춘다. |
| 정보 배치와 절제 | 3 | 카드 그림과 숫자가 잘 분리되고, 빈 길은 넓은 세로 공간을 쓴다. |
| 오류에서 회복 | 2 | 재접속은 복구되지만 배치 불가 이유는 구체적이지 않다. |
| 도움말 | 3 | 규칙, 길별 계산식, 공개 더미 상세가 있다. |
| 합계 | **25/40** | 사용성 평가자의 판단이며 실제 사용자를 모집해 얻은 점수와 구분한다. |

모바일과 노트북 조작부, 탭과 드래그의 구별을 P1으로 평가했다. 점수 설명과 결과 순서는 P2다. 휴대폰으로 판에 복귀하는 사람에게는 차례 표시가, 규칙을 처음 배우는 사람에게는 첫 −15점의 이유가, 키보드를 쓰는 사람에게는 16번의 Tab 이동이 특히 중요하다.

대상 컴포넌트 단일 파일의 정적 디자인 검사 지적은 0건이었다. 실제 브라우저에서는 데스크톱 첫 화면 3건, 모바일 가져오기 단계 13건, 모바일 카드 선택 상태 12건이 나왔다. 상태별 지적은 서로 중복된다. 작은 글자 지적 중 공용 버림 더미의 이름과 장수는 10px라서 모바일에서 키울 후보로 남긴다. 랑이의 보라색은 확정된 계열색이다.
