# 모바일 행동 바와 노트북 손패 조작

Status: resolved
Label: ready-for-agent
Owner: root

## 완료 기준

- 모바일에서 현재 차례를 보고 한 번 눌러 손패 또는 버림 더미를 찾는다. 영역 이동으로 카드를 제출하지 않는다.
- 1366 × 768에서 스크롤 없이 손패 8장과 행동 버튼을 확인한다. 카드 선택 뒤 키보드로 두 번 이내에 행동 버튼에 도달한다.
- 같은 테이블에서 모바일과 노트북 플레이어가 한 턴씩 마치고, 상대 화면의 손패 장수와 덱 장수, 차례가 일치하는지 확인한다.

## 적용 결과

1100px 이하에서 기존 행동 바를 화면 아래에 고정했다. 손패 보기와 버림 더미 보기는 해당 영역에 포커스와 스크롤을 옮긴다. 카드 제출과 덱 뽑기는 같은 바에서 수행한다. 마우스 노트북은 카드 면으로 끌고 터치 노트북은 44px 손잡이를 사용한다. 키보드로 카드를 선택한 뒤 Tab을 한 번 누르면 버리기, 한 번 더 누르면 놓기로 이동한다.

## 플레이 검증

로컬 Chrome의 별도 사용자 두 명이 같은 테이블에 입장했다. 모바일은 터치 입력 에뮬레이션, 노트북은 마우스와 키보드를 사용했다.

- 390 × 844에서 모바일 플레이어가 하단의 손패 보기를 탭하고 물개 6을 골라 버렸다. 가져오기 단계에서 버림 더미 보기를 눌러도 손패는 7장이었다. 덱에서 한 장을 뽑자 손패가 8장이 되고 덱은 43장이 됐다.
- 1366 × 768에서 노트북 플레이어가 물개 2를 고르고 Tab으로 버리기, 다음 Tab으로 놓기에 도달해 Enter로 확정했다. 덱에서 한 장을 뽑자 덱은 42장이 되고 상대 차례가 됐다. 손패 8장과 두 버튼 모두 스크롤 없이 보였다.
- 손패를 스와이프할 수 있는 360px, 390px, 1024px에서 마지막 카드 전체가 행동 바 위에 표시되는 것을 확인했다. 1366 × 768 터치 노트북에서도 손잡이와 행동이 함께 보이는지 별도로 검사했다.
- 관련 E2E 7건, 전체 워크스페이스 타입 검사와 프로덕션 빌드가 통과했다. E2E에서는 자연 종료, 재경기, 가져오기 중 새로고침과 재접속도 확인했다.
- 전체 테스트는 최종 실행에서 168건 통과, 1건 건너뜀으로 끝났다. 앞선 실행에서 저장 복구 네트워크 테스트 두 건이 `SAVE_FAILED`를 반환했다. 해당 테스트 파일의 단독 순차 실행은 4건 모두 통과했고, 이후 전체 재실행에서도 통과했다. 간헐 실패 원인은 확인하지 못했다.
