# 길 예상 점수와 결과 화면

Status: resolved
Label: ready-for-agent
Owner: root

## 완료 기준

- 모바일과 노트북에서 각각 실제 배치 직전의 예상 점수를 읽고 서버 승인 후 같은 길에 표시되는 점수와 대조한다.
- 놓을 수 없는 카드의 이유를 표시하고, 길을 눌러 상세를 여는 동작과 끌어서 놓는 동작을 구별한다.
- 한 판을 자연 종료하고 승패, 점수 차, 준비 버튼이 양쪽 화면에 함께 보이는지 확인한다. 같은 테이블에서 두 사람의 준비 후 새 판을 시작한다.

## 검증 결과

로컬 Chrome의 독립 플레이어 두 명으로 390 × 844 터치 화면과 1366 × 768 노트북 화면을 검사했다. 두 판에서 카드를 놓기 전 표시값을 기록하고, 놓은 직후 내 길과 상대 화면에 공개된 같은 길의 점수를 대조했다. 모바일 16회와 노트북 20회 모두 일치했다.

| 최종 검증 판의 예시 | 놓기 전 길 점수 | 예상 | 승인 후 |
| --- | ---: | ---: | ---: |
| 모바일에서 멍이 9로 길 시작 | 0 | -11 | -11 |
| 모바일에서 랑이 지원 카드 추가 | -40 | -60 | -60 |
| 노트북에서 멍이 지원 카드로 길 시작 | 0 | -40 | -40 |
| 노트북에서 같은 길에 멍이 7 추가 | -40 | -26 | -26 |

규칙 엔진에서는 지원 카드 두 장이 포함된 일곱 장의 길에 여덟 번째 카드 10을 놓는 경우도 검사했다. 15점에서 65점으로 변하는 예상값에 8장 보너스 20점이 포함됐고, 배치 명령을 적용한 뒤 양쪽 플레이어 View의 길 점수와 일치했다.

최종 판은 덱의 44장을 모두 뽑아 노트북 -60점, 모바일 -105점으로 끝났다. 양쪽 첫 화면에서 45점 차 승패, 두 점수, 재경기 준비가 모두 보였다. 두 사람 모두 준비한 뒤 호스트가 같은 테이블에서 덱 44장, 손패 각 8장, 모든 길 0점으로 새 판을 시작했다. 별도로 두 사람이 전부 버리고 덱을 뽑은 판은 0 대 0 공동 승리였고, 모바일 호스트가 재경기를 시작했다. 기권 결과도 양쪽 관점에서 확인했다.

로컬 캡처는 `../score-and-rematch/`에 보관했다. 모바일과 노트북의 예상 점수 및 결과 화면, 재경기 준비 화면은 `tests/e2e/table-play.spec.ts`의 두 플레이어 테스트를 실행하면 다시 생성된다.
