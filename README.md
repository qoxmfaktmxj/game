# 링구링구

친구를 초대해 같은 테이블에서 다섯 게임을 즐기는 **실행 가능한 개발 버전**입니다. 플랫폼은 링구링구, 첫 2인 카드게임은 **로스트 팻츠**입니다. 2026-10-27 사용자가 이름과 B안 대표그림을 확정했으며, 원본 명세의 별길 탐험과 같은 규칙·내부 `star-trails` 식별자를 사용합니다. 추가 네 게임은 공식 기본판의 규칙을 조사하고 자체 이름·그림으로 구현했습니다. 판본과 데이터의 근거는 [게임별 출처 문서](docs/game-expansion-sources.md)에 기록합니다.

홈 → 게임 선택·테이블 생성·초대 → 모두 준비 → 실제 플레이 → 결과 → 동일 테이블에서 재경기·다른 게임 선택이 연결됩니다. 화면은 Next.js·React·Motion, 게임 판정과 통신은 Node.js·Colyseus가 담당합니다.

## 바로 실행

Node.js 24 이상이 필요합니다.

```powershell
npm ci
npm run dev
```

브라우저에서 **http://localhost:3000**을 엽니다. 이 명령은 웹(3000)과 로컬 전용 게임 서버(2567)를 함께 실행합니다.

1. 홈에서 게임을 고르거나 **우리 테이블 만들기**를 누르고 게임·이름·테이블 이름을 정합니다.
2. **초대 링크 복사**로 친구를 부르거나 빈자리의 **연습 봇 추가**로 혼자 시작합니다.
3. 다른 브라우저 또는 시크릿 창에서 링크를 열어 각자 이름으로 입장합니다. 같은 링크로 게임의 정원까지 초대할 수 있습니다.
4. 필요한 인원이 모이면 모두 **준비**를 누르고 호스트가 시작합니다.
5. 게임 화면의 차례·행동 안내를 따릅니다. 규칙 버튼에서 게임별 안내를 볼 수 있습니다.

로컬 프로필은 탭의 sessionStorage에 보관됩니다. 새로고침해도 같은 자리가 유지됩니다. 이 모드는 본인 기기의 loopback 연결용이며 외부 친구가 접속하는 공개 서비스가 아닙니다. 실제 외부 플레이에는 아래 운영 연결이 필요합니다.

## 구현 범위

- 로스트 팻츠의 60장 덱, 배치·버리기·드로우, 점수 산식, 자연 종료와 기권.
- 빛의 공방(2–4명): 개발90장·후원자10개, 자원·예약·구매·반환·최종 라운드.
- 밤의 의회(2–7명): 기본8역할·건물66장, 비공개 선택·역할 능력·도시 건설·특수 건물.
- 황혼의 신호(4–7명): 카드80장·인물16종, 숨김 진영·거리·장비·공격 대응·탈락·팀 승리.
- 넘버가든(2–4명): 타일106개, 30점 최초 등록·전체 보드 재배열·조커·60초 제한·종료 점수.
- 다섯 게임의 중간 난이도 연습 봇: 대기실에서 추가·제거, 자동 준비, 생각하는 지연, 저장·재연결.
- 내 손패만 받는 플레이어별 View, 초대 토큰 해시 저장, 좌석·준비·재경기.
- 명령 직렬화, 중복 요청 재전송, 버전 충돌, 저장 실패 원복.
- 행동마다 저장하고 새로고침·게임 서버 재시작 후 DRAW 단계까지 복구.
- 홈·내 테이블·대기실·게임·결과·규칙 안내·모션 감소, 키보드와 모바일 화면.
- 링구링구의 겹쳐 펼친 카드 로고와 카드 테이블 모션, 새 카드·점수 피드백, 직접 모션 일시정지.
- 대기실·결과의 설정에서 테이블 탈퇴, 수락 후 목록 갱신과 호스트 이전.
- 원본 사진을 사용하지 않은 자체 게임 커버와 게임별 카드 일러스트, 자체 호스팅 글꼴과 라이선스. 로스트 팻츠 대표그림은 숫자 2–10의 3×3 배열과 오른쪽 큰 `×2` 수달 카드로 구성한 B안입니다.

게임별 그림은 개발 서버의 **http://localhost:3000/cards**에서 게임을 선택하거나 게임 화면의 **카드 그림** 링크로 확인합니다. [로스트 팻츠의 동물 카드 50면](docs/card-art.md)과 [추가 네 게임 231종의 이미지·프롬프트 기록](docs/art/README.md)에 개별 생성 결과와 적용 방식을 정리했습니다. 현재 이름·대표그림·색상 선택은 [Open Air 후속 결정](docs/open-air-refinement.md)에 기록합니다.

게임별로 한 판씩 진행합니다. 넘버가든의 교착 동률은 사용자 결정에 따라 공동 승리·전원 점수 합산 없음으로 처리합니다. 게임별 판본과 플랫폼 선택은 [출처 문서](docs/game-expansion-sources.md)에서 구분합니다.

## 프로젝트 구조

| 경로                       | 역할                                            |
| -------------------------- | ----------------------------------------------- |
| `apps/web`                 | Next.js 화면과 클라이언트 연결                  |
| `apps/game-server`         | Colyseus, 인증, 테이블·세션 서비스, 통합 테스트 |
| `packages/game-core`       | 순수 TypeScript 규칙과 테스트                   |
| `packages/contracts`       | 공개 타입과 오류 문구                           |
| `packages/db`              | JSON·PostgreSQL 저장 어댑터와 migration         |
| `tests/e2e`                | 2~4개 브라우저의 게임 조작·모바일·키보드 검증   |
| `moyeotable_build_pack_v1` | 변경하지 않은 기획·규칙·화면 참조               |

## 배포 준비

2026-10-24 결정: **자체 리눅스 서버 · Docker Compose · PostgreSQL**, 도메인 **game.minseok91.cloud**를 사용합니다. 약 8GB RAM을 기준으로 Caddy HTTPS, 웹, 게임 서버, DB, 최소권한 마이그레이션을 준비했습니다. 실제 원격 배포와 DNS 적용은 아직 실행하지 않았습니다.

[배포 절차](docs/deployment.md)와 [오픈클로 인계문](docs/openclaw-handoff.md)을 따라 서버에서 실행할 수 있습니다. 운영은 자체 서명 게스트 인증을 사용하므로 Supabase 계정은 필요하지 않습니다. 기존 Vercel 설정은 이전 경로로 보존합니다.

비밀 키는 웹의 `NEXT_PUBLIC_*`에 넣지 않습니다. `.local-data/`에는 비공개 덱과 손패가 저장됩니다. 이 디렉터리와 원본 사진 참조는 Git 및 공개 빌드 대상에서 제외했습니다.

서버 계약·복구·미구현 운영 정책은 [서버 README](apps/game-server/README.md), 저장 구조 변경 이유는 [ADR](docs/adr/0001-table-aggregate-storage.md)를 참고하세요.

npm run typecheck

npm run test:art
npm run build
