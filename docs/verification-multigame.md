# 다섯 게임·연습 봇·자체 서버 준비 검증

검증일: 2026-10-24(KST). Windows 개발 컴퓨터, Node.js 24.20.0, npm 11.19.0에서 실행했다. 공개 배포나 운영 PostgreSQL 연결 성공을 의미하지 않는다. 개별 카드 일러스트 50종 적용 후 타입 검사·웹 빌드·전체 브라우저 검수까지 완료했다.

## 규칙과 콘텐츠

다섯 엔진은 서버에서 순수 함수로 판정하며 자신의 손패와 허용된 공개 정보만 담은 View를 제공한다. 콘텐츠 판본과 숫자 근거는 [규칙·자료 출처](game-expansion-sources.md), [밤의 의회 콘텐츠 대조](council-content-audit.md)에 기록했다.

| 게임        | 코어 테스트 | 자동 진행 범위                                             |
| ----------- | ----------: | ---------------------------------------------------------- |

이 자동 진행은 규칙 회귀 검증이다. 모든 가능한 상태를 증명하거나 사람과의 장기 플레이 검수를 대체하지 않는다.

## 연습 봇

개인 View만 전달한 봇 정책 시험은 다섯 게임 합계 65판에서 모든 행동이 엔진 검사를 통과하고 자연 종료했다. 별길 탐험 10판·빛의 공방 12판·밤의 의회 18판·황혼의 신호 16판·넘버가든 9판이며 지원 인원 범위를 포함한다. 별도의 넘버가든 봇 시험에서 2–4인 9판을 추가로 진행했다.

고정 난수의 결정성, 입력 불변, 숨긴 덱 순서와 무관한 선택, 일시정지 중 행동 없음, 공격 대상·진영 보호, 숫자 조합·조커 교체를 확인했다. 중간 난이도는 규칙 기반 전략의 설계 목표이며 사람 상대 승률을 측정한 등급은 아니다.

서버 통합 시험은 호스트만 봇을 추가·삭제하는지, 대기실·결과 단계에서만 가능한지, 봇의 자동 준비, 사람 없는 진행 차단, 사람이 끊겼을 때 정지, 재접속과 저장 복원 후 재개, 봇 신원으로 HTTP·소켓 접근 차단을 확인했다. 봇도 사람과 같은 직렬 명령·검증·저장 후 승인 경로를 사용한다.

Windows의 JSON 파일 교체가 일시적으로 실패할 수 있어 복원 시험에도 실제 서버와 같은 1초 스케줄러를 포함했다. 저장 실패 후 승인 없이 다시 시도하고 정상 진행하는 경로를 검증했으며, 저장 실패를 무시하거나 미저장 View를 내보내도록 바꾸지 않았다.

## 실제 통신과 보안 경계

- 별길 탐험은 실제 SDK 2개로 초대·개인 View·뽑기 단계의 서버 프로세스 종료·저장 복구·자연 종료·같은 테이블 재경기를 확인했다.
- 빛의 공방·황혼의 신호·밤의 의회는 각각 실제 SDK 4개로 비공개 정보·프로세스 종료 후 복구·자연 종료·같은 테이블의 다른 게임 선택을 확인했다. 소스 실행과 빌드된 실행 파일에서 모두 통과했다.
- 공통 서비스 시험에서 인증된 행동 주체, 중복 명령, 오래된 버전, 저장 실패, CAS 충돌, 가변 정원, 준비 초기화, 기존 별길 탐험 저장 문서의 호환성을 확인했다.
- 운영 게스트의 서명·만료·세 부분 토큰 문법, 소켓 만료, 로컬 인증의 운영 사용 차단, 봇과 외부인의 접근 거부, 안전한 공개 오류를 확인했다.
- PostgreSQL URL의 `host`·`port`·TLS·세션 옵션 우회 입력을 거절하고, 명시적으로 허용한 사설망 외에는 TLS 검증을 유지하는 설정 시험을 통과했다. 실제 DB 연결 시험과는 구분한다.
- HTTP 요청 제한을 Colyseus 매치메이킹보다 앞에서 적용하는지, readiness와 테이블 경로가 같은 제한을 받는지, 여러 탭의 `sync`와 명령이 사용자별 제한을 공유하는지 실제 요청으로 확인했다.

강제 서버 종료 시험에서는 SDK의 자동 재연결 최소 가동 시간 경고가 출력될 수 있다. 시험은 새 연결로 같은 인증 사용자와 저장된 테이블을 복구하고 결과까지 확인한다.

## 최종 화면 검수

새 일러스트를 실제 공통 카드 컴포넌트에 적용한 뒤 Playwright **12개 시나리오를 한 번의 전체 실행에서 모두 통과**했다(약 1.4분). 다섯 게임의 진행 화면, 봇 추가·삭제·시작과 한 순환, 두 브라우저의 별길 탐험 자연 종료·재경기·DRAW 단계 복구, 네 브라우저의 초대·개인 View, 네트워크 오류 복구, 360px·390px 가로 넘침과 키보드 초점을 포함한다.

갤러리 시험은 고유 이미지 50개의 정상 디코딩과 이미지 응답 오류 없음, 모바일 숫자 배지와 가로 넘침 없음을 확인했다. 데스크톱 갤러리·모바일 갤러리·새 일러스트 손패를 스크린샷으로 직접 확인했다. 원본은 모두 개별 생성했으며 숫자·계열 표시는 HTML/SVG를 유지했다. [이미지와 프롬프트 기록](card-art.md)을 참고한다.

최종 실행 산출물은 `artifacts/card-final-e2e/`이며, 대표 화면은 `card-art-all-50-individual-1220f-d-remain-readable-on-mobile/card-gallery-desktop.png`와 `bots-one-person-adds-and-r-a62d6-isible-turn-then-reconnects/organic-suits-bot-game-390.png`다.

## 나머지 네 게임 카드 아트 적용 후 검증

2026-10-24 새 개별 일러스트 231종(빛의 공방 100, 밤의 의회 36, 황혼의 신호 42, 넘버가든 53)을 적용했다. 기존 50종과 합쳐 총 281종이다. 새 이미지 전체의 고유 해시·1024×1536 PNG·공개 콘텐츠 ID 매핑과 생성 원본 231개를 확인했다.

전체 Playwright **16개 시나리오가 1.5분에 통과**했다. 앞의 12개 시나리오와 네 게임의 전체 이미지 디코딩·모바일 갤러리 검사를 포함한다. 최종 산출물은 `artifacts/all-game-art-final/`이며 실제 게임 화면의 카드·타일 숫자와 인물 구도를 직접 확인했다. 타입 검사, 웹·서버 빌드, 규칙 107개·서버 59개·빌드 서버 SDK 4개 시험도 통과했다. 실제 PostgreSQL 시험 1개는 환경이 없어 건너뛰었다. [새 그림과 프롬프트 기록](art/README.md)을 참고한다.

## 부하 측정

최신 보안 제한을 적용한 별도 로컬 프로세스에서 100개 연결·50개 테이블을 측정했다. 60.08초 동안 4,557개 명령을 승인했고 49개 테이블이 자연 종료했다. 오류 0, 예상치 못한 연결 종료 0이었다. 명령 지연은 p50 **14.37ms**, p95 **39.06ms**, p99 **89.88ms**, 최대 **121.71ms**였다. 원시 결과는 [load-test.json](../artifacts/verification/load-test.json)에 남겼다. 기존 개발 서버를 중단하거나 그 데이터에 테스트 테이블을 만들지 않았다.

측정은 별길 탐험 2인 테이블 50개와 WebSocket 100개를 먼저 연결하고 60초 동안 동시에 진행한다. 명령 전송부터 ACK와 양쪽 개인 View 갱신까지의 지연이며, Windows·localhost·JSON 저장 기준이다. 인터넷 지연, 웹 렌더링, PostgreSQL, 네 게임 혼합 부하, 서버 연습 봇의 조합 탐색 비용, 장시간 누적 데이터를 포함하지 않는다. 실제 8GB 리눅스 서버의 100명 수용 보증으로 해석하지 않는다.

## 아직 실행하지 않은 검증

Docker 이미지 빌드·Compose 기동, 실제 PostgreSQL migration과 RLS, 운영 DB 동시 갱신·복구, Caddy와 DNS·TLS 인증서, 공개 도메인의 실제 두 기기 플레이, 원격 100명 부하, 장시간 운영, 백업·복원은 이 환경에서 실행하지 않았다. 운영 서버와 인증키를 변경하지 않았으며 공개 서비스가 열렸다고 주장하지 않는다. 원격 실행 절차는 [자체 서버 배포](deployment.md), [OpenClaw 인계](openclaw-handoff.md)를 따른다.
