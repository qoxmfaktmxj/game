# 게임별 판정과 공통 테이블의 경계

2026-10-24. 사용자가 공식 기본판을 따르는 추가 네 게임 구현을 승인했다.

테이블 서비스는 인증·좌석·초대·준비·명령 직렬화·중복 방지·저장·연결을 담당한다. 게임별 순수 엔진은 생성·명령 판정·플레이어별 View·결과·저장 상태 검증을 담당한다. 메타데이터는 브라우저가 사용할 수 있는 catalog로 분리하고, 비공개 엔진과 카드 데이터는 서버에서만 실행한다.

공개 RoomView와 저장 세션은 `gameKey`로 좁히는 합집합이다. 테이블 서비스에 게임별 if 문을 반복하지 않고 `multigame.ts`가 각 엔진으로 명령을 전달한다. 새 게임도 현재 세션의 gameKey를 사용하므로 클라이언트가 보낸 게임 식별자로 판정을 우회할 수 없다.

기존 aggregate schemaVersion 1과 SQL 구조를 유지한다. gameKey가 없는 기존 세션만 첫 게임으로 검사해 읽으며, 정상화 후에는 반드시 gameKey가 있다. 신규 상태를 읽을 때 규칙·콘텐츠 버전과 전체 카드·토큰·타일 보존을 검사한다.

플레이 중 연결이 필요한 참가자는 엔진이 정한다. 황혼의 신호에서 탈락한 참가자의 연결은 게임을 멈추지 않는다. 넘버가든의 타이머 변화는 같은 직렬 저장 경로를 통과한다. 연결이 끊기면 남은 시간을 저장하고, 재연결 시 남은 시간으로 이어간다. 타이머는 클라이언트 요청에 의존하지 않는다.

다인 게임의 기권을 '나머지 모두 승리'로 일반화하지 않는다. 현재 기권은 첫 게임에만 제공한다. 호스트는 대기·결과에서 게임을 바꿀 수 있으며 멤버를 보존하고 모두의 준비와 이전 초대를 초기화한다.
