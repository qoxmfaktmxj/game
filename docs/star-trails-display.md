# 별길 탐험의 공개 카드 표시

2026-10-26 사용자 결정. 첫 게임 `star-trails`의 공개 길과 버림 더미를 프리셀처럼 전체 카드가 겹쳐 보이는 방식으로 표시한다. 카드 그림은 확정된 [50면 선택](art/sky-hop-final-selection.json)을 사용한다.

## 보드 표시와 조작

- 상대의 다섯 별길은 위, 버림 더미와 덱은 가운데, 내 별길과 손패는 아래에 둔다.
- 공개 길과 버림 더미는 먼저 쌓인 카드부터 마지막 카드까지 모두 렌더링한다. 이전 카드의 실제 상단 숫자 또는 `×2`가 보이고, 마지막 카드는 전체가 보인다. 최근 네 장 제한이나 별도로 덧씌운 숫자 띠는 사용하지 않는다.
- 별길은 규칙에 따라 놓인 순서를 유지한다. 버림 더미는 버린 순서를 유지하며 숫자순으로 정렬하지 않는다. 배열의 마지막 원소가 가져올 수 있는 맨 위 카드다.
- 각 열의 첫 카드 시작선을 맞추고, 더미가 길어지면 행 높이와 페이지 스크롤이 늘어난다. 뒤따르는 행을 덮거나 고정 높이 안에서 잘라내지 않는다.
- 길과 버림 더미를 누르면 상세창을 연다. 버림 더미의 상세 확인은 카드 가져오기 명령을 보내지 않는다. 별도 `가져오기` 버튼과 상세창의 `마지막 카드 가져오기` 버튼만 실제 가져오기 명령을 보낸다.
- 카드 하단에는 동물 아이콘과 이름만 둔다. 숫자와 `×2`는 상단에 한 번 표시한다. 빈 길은 점선 윤곽과 동물 아이콘만 표시한다.
- 단계 표시는 `놓기·버리기`와 `가져오기`로 구분하고 상대 차례에는 `대기`로 표시한다. 선택한 카드를 길에 내는 버튼은 `놓기`다.
- 설정의 `이번 게임 기권하기`는 왼쪽, `로그아웃`은 오른쪽에 둔다. 앱 개인 모션 감소 토글은 제거하고 OS의 모션 감소 접근성 설정을 따른다.

겹침 간격은 공개 길 데스크톱 32px·모바일 24px, 작은 버림 더미 데스크톱 25px·모바일 21px이다. 표시 간격과 카드 크기의 기준은 [DESIGN.md](../DESIGN.md)와 `apps/web/components/star-board.css`다. 실제 위치와 장수는 저장 승인 후 전달된 View를 따르며, 모션은 이를 꾸미는 피드백이다.

## 숫자·그림·이름의 분리

숫자가 동물 그림을 가리지 않도록 `PlayingCard`를 상단 숫자 행, 가운데 그림 행, 하단 동물 아이콘·이름 행으로 나눈다. 손패·공개 스택·버림 스택·상세창·카드 모아보기·드래그 미리보기에 같은 Grid 구조를 적용한다. 가운데 `.card-art-window`는 상대 위치와 최소 높이 0을 가진 전용 컨테이너다. `Image fill`은 이 컨테이너 안에만 배치하고 `contain`으로 표시한다. 숫자와 이름은 그림 위에 덮지 않는다.

카드 높이는 공개 길 170px·모바일 115px·374px 이하 102px, 버림 더미 124px·모바일 88px·374px 이하 80px다. 손패는 148px·모바일 132px이고, 상세 `.small`은 134px다. 모바일 보드 기준은 640px 이하이며 너비는 기존 열 안에 맞춘다. 덱 뒷면은 버림 카드와 같은 높이다.

상단/하단 행 높이는 기본 32/22px, 모바일 손패와 상세 카드 28/20px, 모바일 공개 길 24/16px, 버림 더미 25/18px·모바일 21/16px이다. 갤러리는 52/40px·760px 이하 44/34px이며 카드 비율 2:3을 유지한다. 숫자/지원 글자 크기는 기본 25/22px, 모바일 손패와 상세 22/20px, 모바일 길 17/15px, 버림 19/17px·모바일 16/14px, 갤러리 36/32px·모바일 29/26px이다. 각 행 사이의 나머지 공간은 그림이 사용한다.

## 원본 규칙 자료와의 차이

[원본 첫 게임 명세](../moyeotable_build_pack_v1/docs/05_game01_star_trails.md)의 **공개 View** 절은 버림 더미에서 맨 위 카드와 장수만 공개하도록 정한다. 이번 결정은 그 조항과 충돌한다. 사용자의 명시적인 전체 더미 표시 요청에 따라 **버림 더미의 모든 카드와 그 순서를 양쪽 플레이어에게 공개**하는 플랫폼 변형으로 변경했다. 원본 패키지 문서는 참조 자료로 보존하고 수정하지 않는다.

공개 View의 각 `discards[suit]`는 기존 `count`와 `top`에 `cards` 배열을 함께 제공한다. `cards`는 오래된 카드부터 최신 카드까지 순서대로 담으며 서버의 저장 배열을 직접 노출하지 않고 복사한다. 이 변경으로 양쪽 플레이어가 이전에 버린 카드를 화면에서 확인할 수 있어 기억에 의존할 필요가 줄어든다.

변경 범위는 버림 더미의 공개 정보다. 다음 규칙과 비공개 경계는 유지한다.

- 가져오기는 해당 더미의 맨 위 한 장만 가능하다. 아래 카드를 선택하거나 건너뛰어 가져올 수 없다.
- 방금 자신이 버린 카드는 같은 차례에 다시 가져올 수 없으며, 그 아래 카드도 가져올 수 없다. 차례·단계·허용 명령은 서버가 판정한다.
- 상대 손패와 메인 덱은 카드 내용을 보내지 않고 장수만 공개한다. 내 손패와 양쪽 공개 길의 기존 공개 범위도 그대로다.
- 50가지 카드 면·60장 덱, 배치 순서, 점수 산식과 종료 조건은 바꾸지 않는다. 지원 카드 표시 `×2`와 누적 점수 배수 `지원 수 + 1`을 구분한다.

## 배포와 확인 범위

웹 화면뿐 아니라 게임 서버의 플레이어 View가 함께 바뀌므로, 배포 시 같은 커밋으로 **웹 `web`과 게임 서버 `game`을 모두 빌드·갱신**해야 한다. 저장 상태에는 이미 버림 배열이 있으므로 공개 배열을 계산하는 데 새로운 저장 필드는 필요하지 않다. 배포 절차는 [자체 서버 배포](deployment.md)와 [OpenClaw 인계](openclaw-handoff.md)를 따른다.

갱신 중 구형 서버의 View를 받는 새 웹은 `cards`가 없으면 기존 `top`을 표시하는 호환 처리를 사용한다. 이는 임시 화면 호환이며, 전체 더미 표시가 적용됐다는 증거가 아니다. 양쪽 서비스를 갱신한 뒤에는 브라우저를 새로고침하고, 두 플레이어의 버림 순서·상세 확인·맨 위 한 장 가져오기·같은 차례 재가져오기 제한·재접속 후 표시를 확인한다.

이 문서는 사용자 결정과 구현 계약을 기록한다. 원격 서버 업데이트, 운영 PostgreSQL, 인터넷 대전이나 실제 배포 완료를 검증했다는 주장은 포함하지 않는다.
