# 링구링구 구현 검증

검증일: 2026-10-23 (Asia/Seoul). Node.js 24.20.0, npm 11.19.0, Windows 로컬 개발 환경. 원본 패키지의 기존 검증과 이번 구현 검증을 구분한다.

## 실행한 검사

| 검사 | 결과 | 실제 범위 |
| --- | --- | --- |
| `npm run typecheck` | 통과 | 웹·서버·계약·DB·규칙 패키지 strict 타입 검사 |
| `npm test` 및 운영 회귀 추가 실행 | 규칙 41개 + 서버 14개 통과 | 전체 41+13 통과 후 운영 회귀 1개 추가, 해당 운영 파일 4개 재검증 |
| `npm run build` | 통과 | 실행용 서버 번들 + Next.js 프로덕션 빌드 |
| `npm run test:built --workspace @moyeotable/game-server` | 1개 통과 | 빌드된 Node 서버로 실제 두 클라이언트·프로세스 복구·자연 종료·재경기 |
| `npm run test:e2e` | 최종 5개 통과 (약 5.1분) | 실제 Chrome 독립 컨텍스트·모바일·모션·키보드·단절 복구·탈퇴·일시 오류 |
| 의존성 설치 시 npm audit | 발견 사항 0개 | 설치된 lockfile 기준. 전체 보안 검증을 뜻하지 않음 |
| Impeccable 정적 검사 | 후속 디자인에서 토큰 문서 advisory 발생 | 색·크기·반경 문서 범위 경고 확인. 출력이 잘려 전체 정적 검사 통과로 주장하지 않음 |

규칙 테스트는 100판, 8,800개 명령의 자연 종료를 포함한다. 매 단계 카드 60장 보존, 올바른 단계·차례, 엄격 증가, 지원 카드 순서, 점수, 입력 변조, 원본 불변성, 플레이어 View의 비밀 정보 누출을 검사했다.

서버 테스트는 실제 Colyseus SDK 클라이언트 두 개와 별도 Node 프로세스를 사용한다. 인증된 주체, 초대·좌석, 준비 초기화, 명령 중복/변조/경쟁/버전 충돌, 저장 실패 시 원복, 이전 소유자의 쓰기 거절, 멤버 퇴장·방장 이전, 단절 시 행동 정지와 재개를 확인했다. DRAW 단계에서 프로세스를 강제 종료한 뒤 동일 토큰·테이블·세션·손패·덱으로 복구했다. 전체 덱 소진과 새 세션의 재경기를 확인했다.

브라우저 검증은 실제 UI의 테이블 생성·초대·두 사람 준비·카드 배치/버리기/뽑기를 사용한다. 최종 4개 검사는 44턴 자연 종료, 결과 합의, 재경기, DRAW 새로고침, 360px·390px 홈/대기/게임/결과의 가로 넘침, 모달 초기 포커스·Tab 순환·Escape 복귀를 통과했다. 초기 HTTP 검증에 503을 주입해 기존 토큰·좌석이 유지되고 새 게스트를 발급하지 않으며 복구 후 준비 명령이 성공함을 확인했다. 시스템 모션 감소가 꺼진 상태에서도 설정 토글이 실제 카드 CSS 전이를 줄이는 것을 검증했다.

웹의 프로덕션 정적 번들에서 `guest-signing-secret`, `game_private`, `JsonTableRepository`, `justDiscardedId`가 포함되지 않은 것을 검색으로 확인했다. 이는 서버 전체의 보안 감사가 아니다. `.local-data/`와 원본 `references/` 경로가 Git ignore 대상임을 확인했다.

## 화면 검수

독자 제작 SVG와 로컬 호스팅 글꼴로 홈·대기실·게임·결과를 렌더링했다. 데스크톱과 390px·360px 모바일에서 확인했으며, 손패 영역만 가로 스크롤한다. 원본 사진은 런타임에 사용하지 않았다.

검수 중 글꼴 CSS 경로, 모달 초기 포커스·포커스 순환, 360px 규칙 버튼 노출, 이전 테이블 초대 링크 복사, 만료 세션 재연결, 로그아웃 시 View 제거, 일시 연결 오류 시 로컬 신원 보존을 수정했다. 카드 계열 텍스트 색을 조정해 각 실제 손패 배경과의 대비를 약 4.91:1~6.27:1로 높였다. 장식과 모든 화면의 전체 WCAG 적합성을 인증한 것은 아니다.

캡처는 `artifacts/verification/`에 보존한다. 실제 사용자가 없는 테스트 이름·테이블이며, 화면 캡처용으로 게임 상태를 조작하지 않는다. full-page 캡처 전 문서 상단으로 이동해 고정 요소가 잘못 합성되는 문제를 줄인다.

첫 플레이 버전의 독립 디자인 리뷰는 홈·대기·진행·결과·규칙의 데스크톱 및 360px·390px 캡처와 소스를 확인하고 `ship`으로 판정했다. 검토 범위에서 남은 중대 시각·사용성 문제를 발견하지 않았으며, 카드 대비와 캡처 겹침 수정도 재확인했다. 이 판정은 캡처 기반 검토이며 브라우저 기능 검사 및 외부 연동 검증과 구분한다.

## 링구링구 개선 (2026-10-23 후속)

표시 이름·고리 로고·favicon을 링구링구로 바꾸고 원형 테이블 위 카드 모션을 추가했다. 홈 모션은 직접 정지할 수 있으며 화면 밖·탭 비활성·OS/앱 움직임 줄이기 설정에서 멈춘다. 게임에서는 서버가 승인한 새 카드·점수만 짧게 움직인다. OS 모션 감소로 인한 SSR hydration 불일치를 수정하고 새 브라우저의 console/pageerror가 없는 것을 확인했다.

서버 준비 상태 `/readyz`, 저장소 점검 후 기동, PostgreSQL 인증서 검증·pool/timeout 설정, 인증 서버의 임시 장애와 429의 503 구분, 만료된 socket 종료를 추가했다. 운영 테스트는 로컬 가짜 Auth 업스트림과 JSON 저장소 실패 주입을 사용한다. 실제 PostgreSQL TLS·RLS 또는 외부 인증 성공을 검증했다는 의미가 아니다.

독립 소스 리뷰에서 재연결 중 저장소 장애를 401로 처리하는 문제와 LEAVE 수락 뒤 목록조회 실패 시 테이블 화면에 남는 문제를 발견해 수정했다. 새 서버 회귀는 저장소 실패 중 실제 Colyseus join의 503 응답·상세 비노출과 복구 후 동일 테이블/멤버 입장을 통과했다.

최종 E2E 5개를 한 번에 실행해 모두 통과했다(약 5.1분). 기존 자연 종료·재경기 이후 실제 상대 탭 이탈과 동일 손패 복귀, 다음 명령 성공, 모바일 기권, 호스트 탈퇴·남은 멤버의 호스트 승계·준비 초기화까지 확인했다. 별도 테스트는 탈퇴 ACK 뒤 목록 조회만 503으로 실패시켜도 URL과 로비 이동이 유지되고 다음 테이블 생성 화면을 사용할 수 있는지 검증했다. 홈의 무한 모션 running/paused와 OS 감소 설정에서 실행 중 애니메이션이 없는지도 검사했다. 확장된 첫 시나리오에 기기 경합 여유를 주기 위해 timeout을 360초로 설정했으며 44턴과 검증 조건은 유지했다.

최종 수정본 전체 타입 검사·서버/웹 빌드와 빌드된 서버의 2클라이언트 프로세스 복구 테스트도 통과했다. 최신 12개 화면 캡처와 별도 홈 히어로 캡처를 `artifacts/verification/`에 보존했다. 별도의 독립 시각 리뷰는 최신 홈·게임·결과·대기·규칙 캡처 10개 및 관련 모션 코드를 확인해 `ship`으로 판정했다. 전체 접근성 적합성이나 실제 연속 모션의 성능 인증을 뜻하지 않는다.

## 아직 실행하지 않은 것

- 실제 Supabase 계정 두 개의 이메일 로그인 및 인증 콜백.
- 원격 PostgreSQL migration 적용, 서버 역할·RLS 권한과 실제 DB의 저장 실패/복구.
- 외부 네트워크에서 친구 두 명 접속, HTTPS/WSS·호스팅·도메인·클라우드 배포.
- 10판 지인 사용자 검수, 부하/지연 측정, 운영 로그·백업 복원.
- 이 저장소의 GitHub Actions 실행. CI 구성 파일만 작성했으며 push하지 않았다.

## 남은 제품·운영 작업

방장 이탈 60초 후 자동 위임, 단절 180초 후 기권/무효 선택, 빈 Room 15분 유지, 전원 오프라인 24시간 종료, 비밀 스냅샷·명령 기록 자동 삭제는 아직 구현하지 않았다. 단절 시 행동 정지와 같은 계정의 복귀는 구현되어 있고, 서버 장애를 패배로 처리하지 않는다. 명시적 기권은 모바일 설정에서도 가능하다.

닉네임 변경, 결과에서 대기실로 돌아가는 별도 명령, 공개 행동 기록 UI는 후속 항목이다. 대기실·결과의 설정에 테이블 탈퇴 UI를 추가했다. 게임 중에는 기권 후 결과 화면으로 이동하거나 같은 테이블에서 양쪽 준비를 다시 확인해 재경기한다.

현재 저장소는 단일 게임 서버를 전제로 한다. JSON 어댑터는 로컬 전용이고, PostgreSQL도 다중 인스턴스 소유권 임대를 구현한 상태가 아니다. 장기 테이블의 명령/결과 문서 크기 관리가 필요하다. 상세는 `apps/game-server/README.md`를 따른다.

이 결과는 **로컬에서 실제 2인 플레이와 복구를 검증한 개발 버전**이며, 운영 환경에서 공개 서비스를 검증했다는 의미가 아니다. 사용자 결정으로 실제 인증·DB 연결 및 배포는 이후로 미뤘으며 Vercel 기준 준비 상태를 `docs/deployment.md`에 기록했다.
