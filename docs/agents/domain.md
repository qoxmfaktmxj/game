# Domain docs

This repository uses a single domain context. Package boundaries do not create separate domain vocabularies.

Read the root `GLOSSARY.md` and relevant decisions in `docs/adr/` before exploring a domain. If they are absent, proceed silently. If a `GLOSSARY-MAP.md` is later introduced, follow its pointers for the relevant contexts.

Use the glossary's terms. When a new proposal conflicts with an existing decision, name the conflict and trade-off instead of silently replacing the decision. Create domain documentation lazily when a term or decision has actually been resolved.
