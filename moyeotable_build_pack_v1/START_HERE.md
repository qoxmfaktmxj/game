# 모여테이블 | 개발 기준 패키지 v1.0
작성: 2026-10-23 · 서비스명과 자체 게임명은 가칭입니다.

## 무엇이 완료되었나
공개 웹사이트 안에서 초대된 친구끼리 여러 게임을 즐기는 서비스를 위한 개발 계획, 화면 시안, 첫 게임의 실행 가능한 규칙 참조 코드와 테스트를 제공합니다. **온라인 멀티플레이 제품 완성본은 아닙니다.**

- 확정 요구: 브라우저 실행 / 공개 사이트 / 무료 이용 / 초대 중심 플레이 / 원작 규칙만 참고 / 이름·코드·아트·설명·화면 독자 제작.
- 제안 기준: Next.js + React + TypeScript + Motion, Node.js + Colyseus, Supabase Auth + PostgreSQL.
- 최초 구현: `별길 탐험(star-trails)`의 기본 2인·단판 규칙. 제공 사진의 규칙을 작동 방식으로 다시 정리했고, 원작 문장과 아트를 런타임에 사용하지 않습니다.
- 이후 확장: 빛의 공방 → 밤의 의회 / 황혼의 신호 / 넘버가든. 뒤의 4개는 확장 설계입니다. 카드 전체 데이터·판본·예외가 확정된 완성 명세가 아닙니다.

## 읽는 순서
1. `Moyeotable_Development_Plan_v1.pdf`: 사람이 읽는 통합 기획서.
2. `docs/00_decisions.md` → `docs/05_game01_star_trails.md`: 개발 기준과 첫 게임 명세.
3. `prototype/index.html`: 압축 해제 후 브라우저에서 열어보는 화면 프로토타입. 화면 이동·선택·확인·다시하기 UI만 시연하며 서버와 연결되지 않습니다.
4. `rules-reference/`: Node.js로 실행하는 규칙 참조 코드와 테스트. `cd rules-reference && npm test`.
5. `prompts/00_bootstrap.md`: 개발 AI에 전달할 시작 프롬프트.

## 기준 문서의 우선순위
`docs/00_decisions.md` → 게임별 명세 → 계약/DB 명세 → 화면 명세 → 화면 시안 → 참고 콘셉트 이미지 순입니다.
이미지 속 글자, 기간, 기술 버전, 게임 배치, 숫자는 규칙의 근거가 아닙니다. 충돌하면 코드로 임의 보정하지 말고 명세 변경을 기록하세요.

다섯 게임 동시 구현, 원작 카드 스캔 배포, 클라이언트에서 승패 확정, 전체 손패 브로드캐스트, AI 콘셉트 이미지 숫자를 규칙으로 채택, 게임 서버를 프런트엔드 앱과 혼동하는 작업을 하지 마세요.
