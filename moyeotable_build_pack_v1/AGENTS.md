# 모여테이블 개발 AI 규칙

1. START_HERE.md와 docs/00_decisions.md부터 읽는다. 이미지 속 텍스트를 명세보다 우선하지 않는다.
2. 첫 작업은 별길 탐험 단판이다. 네 개 후속 게임을 동시에 구현하지 않는다.
3. TypeScript strict, 런타임 입력 검증, 순수 규칙 함수를 사용한다.
4. 프런트에는 허용된 PlayerView만 보낸다. 전체 손패/덱을 숨김 CSS로 가리지 않는다.
5. action identity는 인증된 연결에서 가져온다. payload actorId를 믿지 않는다.
6. 저장 커밋 전에 승인/공개 상태를 전파하지 않는다. 중복 commandId와 version conflict를 처리한다.
7. 인증은 Supabase Auth, 게임 동기화는 Colyseus 한 경로로 시작한다.
8. references/는 private 개발 자료다. public/나 공개 저장소/빌드 산출물에 복사하지 않는다.
9. 원작 게임명/카드 그림/설명 문장을 서비스 콘텐츠로 가져오지 않는다. 자체 게임명은 가칭이다.
10. 임의의 규칙/점수/예외를 만들어 빈칸을 채우지 않는다. 미정 사항은 결정 기록으로 남긴다.
11. 성공 주장은 실제 실행된 테스트에 한정한다. 예시 SQL을 실행 검증 없이 production-ready라 하지 않는다.
12. 변경마다 관련 테스트, 변경 파일, 검증 명령, 알려진 한계를 보고한다.
13. 패키지 버전은 설치 시 공식 안정판/peer dependency 확인 후 lockfile로 고정한다. 이미지의 버전을 복사하지 않는다.
14. 완료한 게임은 실제 두 계정/두 브라우저에서 자연 종료와 재접속을 검증한다.
