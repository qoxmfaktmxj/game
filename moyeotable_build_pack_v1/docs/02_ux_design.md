# 02. 화면·상호작용 설계

## 시각 방향
'따뜻한 카페'는 로비에서 표현하고 게임 중에는 정보 가독성을 우선합니다. 진한 잉크색 바탕, 부드러운 크림색 카드, 민트 강조, 절제된 그림자를 사용합니다. 장식은 클릭 대상을 가리지 않습니다. 카드 숫자·기호·점수는 이미지에 구워 넣지 않고 HTML 텍스트로 표시합니다.

## 화면 목록과 필수 상태
| 화면 | 핵심 콘텐츠 | 반드시 구현할 예외 |
|---|---|---|
| 홈페이지 | 소개, 게임 목록, 시작, 초대 입장 | 인증 실패·네트워크 오류 |
| 내 테이블 | 참여 테이블, 새 테이블, 게임 소개 | 목록 없음·권한 없음 |
| 테이블 대기실 | 좌석, 준비, 초대, 게임 선택 | 가득 참·토큰 만료·멤버 변경 |
| 게임 | 상대 공개 정보, 보드, 버림 더미, 내 손패, 로그 | 차례 아님·잘못된 행동·연결 끊김 |
| 결과 | 점수 산식, 승패, 기권 사유, 재경기 | 동점·무효 종료 |
| 설정 | 소리, 모션 줄이기, 닉네임 | 저장 실패 |

## 별길 탐험 데스크톱
상단: 테이블명·연결 표시·현재 차례·남은 덱 수. 중앙: 상대 경로 → 공동 버림 더미 → 내 경로. 하단: 손패 8장과 다음 행동 안내. 우측: 공개 행동 로그와 규칙 도움말. 공개 기록에는 비공개 뽑기 카드 이름을 적지 않습니다.

## 별길 탐험 모바일
세로 화면은 상단 상태바, 상대 경로 요약, 공동 더미, 내 경로, 가로 스크롤 손패, 하단 실행 버튼 순서입니다. 작은 5열 보드에서 모든 카드 그림을 보여주려 하지 말고 경로의 마지막 숫자·지원 개수·장수·예상 점수를 먼저 보여줍니다. 경로 터치로 상세 패널을 엽니다. 390px 기준 가로 페이지 넘침이 없어야 하며 손패 컨테이너만 가로 스크롤됩니다.

## 입력 규칙
- 기본: 카드 선택 → 놓을 경로/버리기 선택 → 서버 요청. 드래그는 보조 입력으로만 추가합니다.
- 선택 중 취소는 가능하지만 서버가 이미 승인한 행동은 되돌리지 않습니다. 상대에게 공개된 정보를 되감지 않습니다.
- PLACE 승인 후 DRAW 단계에서만 덱 또는 버림 더미를 고릅니다. 두 단계 각각 저장됩니다.
- 요청 중 버튼 잠금과 clientCommandId 재사용으로 중복 입력을 방지합니다. 낙관적 연출이 가능해도 점수/차례는 서버 승인 전 확정하지 않습니다.
- 명령 실패 시 카드가 출발 위치로 돌아오고 오류 이유를 한국어로 표시합니다.
- 모바일 터치 목표 최소 44px를 제품 기준으로 삼고 키보드 Enter/Space·포커스를 지원합니다.

## 애니메이션 제안
선택 120ms, 카드 이동 220ms, 정렬 180ms, 결과 400ms. 서버 상태와 독립된 프레젠테이션 레이어입니다. prefers-reduced-motion에서는 이동/흔들림을 줄이고 상태 변화는 유지합니다. 모션 종료를 기다려야 규칙 처리가 진행되는 설계는 피합니다. Motion의 레이아웃 기능은 [S05]에서 확인했습니다.

## 색상과 기호
aurora=원, ember=삼각형, tide=마름모, moss=사각형, dusk=별. 색을 못 구분해도 기호·이름으로 경로를 찾을 수 있게 합니다. 공개된 카드와 내 손패는 숫자를 확대할 수 있어야 합니다.

## 프로토타입의 범위
동봉 HTML은 홈·로비·대기실·게임·결과의 클릭 흐름과 반응형 배치를 검토하기 위한 것입니다. 로그인·초대 링크·실제 네트워크 대전은 구현하지 않았습니다. 시안의 버튼을 눌렀다고 서버 명령이 실행되는 것은 아닙니다.
