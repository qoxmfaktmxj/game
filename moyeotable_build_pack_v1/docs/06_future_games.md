# 06. 나머지 네 게임의 확장 계획
이 문서는 다음 게임의 설계 과제와 공통 엔진 요구사항을 정의합니다. 원작 판본의 모든 예외 규칙과 카드 데이터를 검증한 완성 명세는 아닙니다. 표의 인원은 이 서비스가 초기 목표로 잡은 범위입니다.

## 빛의 공방 — 자원 수집·구매·영구 할인
참고 대상: 스플렌더 계열. 가칭 테마: 빛 조각을 모아 장치를 제작하는 공방. 목표 인원 2~4명.
- 공개 상태: 공용 자원 풀, 등급별 카드 시장, 플레이어 보유 자원·영구 생산·점수.
- 비공개 상태: 덱 순서, 비공개 예약을 선택하는 경우 예약 카드 상세.
- 핵심 명령: TAKE_RESOURCES, PURCHASE, RESERVE, RETURN_RESOURCES, CLAIM_OBJECTIVE.
- 상태 단계: ACTION → 필요 시 RETURN/OBJECTIVE_CHOICE → END_TURN. 자원 상한 초과 선택이 남아 있을 때 다음 차례로 넘기지 않습니다.
- 구현 전 확정: 인원별 자원 수, 동색 2개 획득 조건, 서로 다른 색 부족 시 처리, 예약 상한·보충·대체 자원, 목표 달성 선택, 종료 라운드와 동점 처리.
- 데이터: 독자 카드 비용/점수/생산 목록과 목표 카드 목록. 원작 카드 배열을 이미지에서 전사하지 않습니다. 새 밸런스라면 20판 이상 내부 플레이 데이터를 목표로 검토하되, 이 패키지에서 밸런스 검증을 했다고 표시하지 않습니다.
- 통과 시험: 구매에서 영구 할인/와일드 자원 계산, 자원 보존, 예약 노출 범위, 여러 목표 동시 충족, 마지막 라운드 순서, 3·4인 재접속.
- 출시 게이트: 별도 `rules/light-workshop-1.0.0.md`와 전체 카드 데이터, 독립 점수 오라클 완료.

## 밤의 의회 — 비밀 역할 선택·능력·건설
참고 대상: 시타델 계열. 가칭 테마: 밤의 도시를 복원하는 의회. 초기 목표 인원 4~6명. 원작의 모든 인원 변형을 처음부터 지원한다고 약속하지 않습니다.
- 공개: 자원, 건설된 시설, 현재 호출 순서, 공개된 역할.
- 비공개: 선택 가능한 역할 풀, 선택 결과, 손패, 탈락/미선택 역할.
- 단계: ROUND_SETUP → ROLE_DRAFT → ROLE_CALL → RESOURCE_ACTION → ABILITY/BUILD → ROUND_END.
- 구현 전 확정: 역할 종류·능력·호출 순서, 인원별 역할 제외 방식, 능력 대상/미존재 대상, 여러 능력 사용 순서, 건설 상한·동일 시설, 도시 완성 종료·동점.
- 통과 시험: 역할 선택이 다른 플레이어에 노출되지 않음, 호출해도 없는 역할 건너뛰기, 자원 획득/능력/건설 순서, 선택 중 재접속.
- 출시 게이트: 역할/시설 전체 데이터와 각 능력의 허용 phase·target·공개 범위 확정.

## 황혼의 신호 — 숨은 진영·공격/대응·탈락
참고 대상: 뱅 카드게임 계열. 가칭 테마: 사막 관측소의 신호 쟁탈전. 초기 목표 4~7명.
- 공개: 체력에 해당하는 안정도, 공개 리더, 장착 장치, 손패 장수, 생존자.
- 비공개: 진영/역할, 손패, 덱.
- 단계: TURN_BEGIN → ACTION → AWAIT_RESPONSE → RESOLVE_EFFECT → DISCARD_DOWN → TURN_END.
- 핵심은 `activeTurnPlayer`와 `allowedResponders`를 구분하는 것입니다. 다른 사람 차례의 응답을 공통 엔진이 일괄 차단하면 안 됩니다.
- 구현 전 확정: 좌석 거리/탈락 후 거리, 공격 횟수, 대응 범위, 연쇄 효과 큐, 동시에 여러 대상이 응답하는 순서, 덱 재생성, 탈락 보상/벌점, 각 진영 승리 우선순위.
- 타임아웃: 어떤 응답을 기본으로 처리할지 별도 합의합니다. 무응답을 임의 카드 소비로 바꾸지 않습니다.
- 통과 시험: 다중 대상 효과 큐, 탈락으로 대상이 사라짐, 효과 처리 중 승리, 비밀 역할 로그 노출, 응답자의 네트워크 이탈.
- 출시 게이트: 모든 카드 효과가 명시된 유한 상태 전이와 테스트 시나리오 확보.

## 넘버가든 — 숫자 타일 묶음·재배열
참고 대상: 루미큐브 계열. 가칭 테마: 숫자 정원을 배열하는 추상 타일 게임. 초기 목표 2~4명.
- 공개: 확정된 보드 묶음, 플레이어 랙 장수, 남은 타일 수.
- 비공개: 내 랙/다른 사람 랙, 뽑기 순서. 작업 중 타일 배치는 MVP에서 상대에게 스트리밍하지 않습니다.
- 입력: 작업 복사본에서 드래그/키보드로 재배열 → SUBMIT_BOARD 한 번으로 제출. 서버 확정 보드는 승인 전 변하지 않습니다.
- 검증: 이전 보드 타일은 삭제/복제 불가. 새 타일은 자기 랙에서만. 모든 묶음의 길이·색·값·조커 배치가 유효. 랙/보드/주머니 총량 보존.
- 구현 전 확정: 최초 등록 합계·등록 전 보드 조작 허용, 조커 회수/대체/다중 조커, 연속 수의 끝 연결 금지 여부, 못 놓았을 때 뽑기와 차례, 제한 시간·벌점, 빈 주머니/교착·동점.
- 통과 시험: 조커가 포함된 묶음 분해/재결합, 타일 ID 복제 공격, 작업 취소, 제한 시간 종료 복귀, 모바일 확대/스크롤과 드래그 충돌.
- 출시 게이트: 전체 타일 데이터와 valid/invalid 보드 고정 fixture 최소 50개 확보.

## 개발 순서 결정
별길 탐험으로 2인 공통 기능 검증 → 빛의 공방으로 3·4인과 자원 선택 흐름 검증 → 실제 친구 수요에 맞춰 밤의 의회/황혼의 신호/넘버가든 선택. 다섯 게임의 이름을 로비에 보여주더라도 미구현 게임은 '준비 중'으로 표시하고 시작 버튼을 막습니다.
