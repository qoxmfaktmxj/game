# 01. 제품 요구사항

## 제품 문장
공개된 홈페이지에서 친구에게 초대 링크를 보내고, 같은 테이블에 모여 게임을 고르고, 한 판이 끝나면 다른 게임으로 이어가는 무료 웹 보드게임 공간.

## 출시 범위
| 단계 | 포함 | 제외 |
|---|---|---|
| 첫 구현 | 초대, 로그인, 닉네임, 2인 준비, 별길 탐험 단판, 결과, 재경기, 재접속 | 공개 자동 매칭, 관전, 랭킹, 음성, 결제 |
| 두 번째 게임 | 2~4인, 게임 교체, 빛의 공방 규칙/데이터, 좌석 재선택 | 동시 다섯 게임 출시 |
| 운영 강화 | 신고/차단, 모니터링, 백업 복구, 관리 화면 | 광범위한 소셜 피드 |
| 후속 | 역할 게임, 타일 게임, 관전의 별도 정보 정책 | 완료 여부를 미리 표시하지 않음 |

## 공개 홈페이지와 비공개 테이블
홈페이지와 게임 소개는 누구나 볼 수 있습니다. 테이블 목록·멤버·채팅·게임 진행은 해당 테이블 멤버에게만 보입니다. 초대 링크가 없으면 임의 tableId를 알아도 들어가지 못합니다. 공개 검색형 테이블은 별도 기능으로 남깁니다.

## 핵심 사용자 여정
1. 홈페이지에서 시작 → 로그인 → 닉네임 지정. 인증 콜백 후 원래 초대 목적지로 돌아갑니다.
2. 테이블 생성 → 초대 링크 복사 → 친구 로그인/가입 → 좌석 점유.
3. 게임 선택 → 필요한 인원 모두 준비 → 방장이 시작. 준비 후 규칙/멤버가 바뀌면 모두 준비 해제.
4. 내 차례에는 가능한 행동을 보여주고, 완료 후 상대가 같은 확정 상태를 받습니다.
5. 재접속 시 내 좌석과 손패를 복구합니다. 다른 사람의 손패는 어떤 응답에도 포함하지 않습니다.
6. 결과 → 재경기 또는 대기실로. 재경기는 새 sessionId·새 덱·새 준비 확인으로 시작합니다.

## 테이블 정책
- DB 모델은 최대 8석을 수용하지만, 첫 UI는 2석만 활성화합니다. 게임마다 지원 인원이 다릅니다.
- 방장은 대기실에서 게임 변경·초대 폐기·시작·방장 위임을 할 수 있습니다. 진행 중 덱/손패 열람이나 마음대로 점수 변경은 못 합니다.
- 게임 중 신규 참가자는 활성 좌석에 들어가지 못합니다. MVP는 관전 화면을 제공하지 않습니다.
- 활성 참가자가 탈퇴 버튼을 누르면 기권 확인을 보여줍니다. 대기실 퇴장과 게임 기권을 구분합니다.
- 모든 사용자가 나가면 15분 동안 테이블을 보관한 뒤 접속용 Room을 닫습니다. 테이블·세션 영구 기록은 DB 정책에 따릅니다.
- 방장이 대기실에서 이탈하고 60초 내 복귀하지 않으면 가장 오래 접속 중인 멤버로 위임합니다. 이 수치는 서비스 제안 기본값입니다.

## 초대 링크 정책
서버가 32바이트 암호학적 난수 토큰을 만들고 DB에는 해시만 저장합니다. 만료 24시간, 사용 가능 횟수는 빈 좌석 수로 설정합니다. 토큰만으로 계정 권한을 대신하지 않습니다. 사용 시 로그인한 userId에 멤버십을 부여합니다. 방장은 토큰을 재발급/폐기할 수 있습니다. URL에 액세스 JWT·재접속 토큰을 넣지 않습니다.

## 이탈·지연·기권 제안
연결이 끊기면 새 게임 명령을 일시 중지하고 180초 복귀 유예를 둡니다. 복귀 후 최신 상태를 받아 계속합니다. 유예가 지나면 남은 플레이어가 '상대 기권으로 종료' 또는 '무효 종료' 중 선택합니다. 이 결과는 일반 점수 승리와 다른 reason으로 기록합니다. 서버 장애는 플레이어 패배로 처리하지 않습니다. 전원이 오프라인인 세션은 최대 24시간 복구 가능 상태로 보관 후 무효 종료합니다.

## 첫 출시에서 측정할 것
친구 2명이 다른 네트워크에서 입장 가능한지, 한 판 종료율, 명령 실패 종류, 재접속 성공률, 상태 불일치/중복 반영 건수, 서버 명령 응답 p95입니다. 목표치는 검수용 가설이며 달성된 실적으로 쓰지 않습니다.
