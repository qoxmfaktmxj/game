# 08. 단계별 백로그와 완료 조건
일정은 달력이 아니라 완료 조건으로 관리합니다. 기존 이미지에 표시된 기간은 폐기합니다. 작업량은 실제 첫 스프린트 속도를 보고 추정합니다.

| Gate | 작업 | 산출물 | 통과 조건 |
|---|---|---|---|
| G0 기준 고정 | 범위·규칙·프로토콜·이미지 경계 확인 | ADR, 규칙1.0, 테스트 목록 | 원작 이미지 없이 기본 게임 설명 가능 |
| G1 순수 규칙 | 덱·진행·점수·View | 게임 모듈·단위 테스트 | 정상/예외·카드 보존·비밀 미전송 |
| G2 서버 계약 | 인증·Room·멤버십·명령·DB | 서버 API·소켓·마이그레이션 | 인증/중복/동시 명령/DB 실패 시험 |
| G3 실제 2인 | 대기실·손패·선택·드로우·결과 | 네트워크 플레이 | 두 브라우저 한 판 완료·점수 일치 |
| G4 복구·모바일 | 재접속·재시작·반응형·접근성 | 장애/E2E 보고 | DRAW 복구·모바일 조작·비밀 패킷 검사 |
| G5 비공개 테스트 | 지인 초대·피드백·에셋 정리 | 출시 체크리스트 | 실제 10판·차단 결함0·권리/공개 정책 |
| G6 두 번째 게임 | 2~4인·자원·시장·새 데이터 | 빛의 공방 별도 명세/구현 | 게임 교체와 4인 복구 검증 |
| G7 후속 확장 | 역할 또는 타일 게임 | 각각의 모듈 | 각 게임 규칙/데이터/시험 완료 |

## 병렬화 원칙
규칙 담당과 화면 담당은 contracts가 고정된 뒤 병렬 작업합니다. 서버/DB 변경은 하나의 PR에서 저장·복구 테스트를 함께 제출합니다. 디자인 담당은 원작 사진을 런타임 이미지로 복사하지 않습니다. 리뷰 없이 규칙 숫자나 동점 조건을 바꾸지 않습니다.

## 게임을 더 넣기 전에 확인
첫 게임용 특수 조건이 공통 Room을 오염시키지 않는지, 2석을 상수로 박지 않았는지, activePlayer 외 응답자를 지원할 수 있는지, Tile draft처럼 임시 배치를 따로 다룰 수 있는지 점검합니다. 필요하지 않은 범용 DSL을 먼저 만드는 일은 피합니다.
